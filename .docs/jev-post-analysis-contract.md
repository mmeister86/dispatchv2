# Jev post analysis v1

`jev-post-analysis-v1` is an immutable content rubric: one eight-label choice, five ordered five-level scores and three scalar probabilities. Questions evaluate wording and intent, never future reach, clicks or comments. The absence of a CTA is the neutral middle level by rubric assumption. No novelty against unseen posts or factual truth is inferred. `jev-normalization-v1` uses the pinned SDK's fractional zero-indexed score divided by four; confidence remains separate, scalar noul has no invented confidence. Invalid, missing, nonfinite or out-of-range results are rejected by the existing runtime normalization.

The internal `ai/jev/analyzePost:analyze` action consumes the exact authenticated current saved draft version, account, complete ordered thread, provenance/source horizon and factual media metadata through the reviewed admission context. It sends only ordered text, factual media metadata, network and declared audience context. Account/draft/version IDs, capability and provenance/source-horizon proofs remain server-side; it sends no image bytes and makes no visual inference. All protected research lineage and immutable media SHA/object keys retain the existing current-authority checks. UTF-8 bytes conservatively bound the complete request against the approved input budget; an oversized complete input is refused, never sliced. This action is an internal preparation boundary, with no persistent shadow assessment or public arbitrary-questions API. Durable versioned assessments/current projections/cache belong to TASK-28.3.

`structure-v1` averages four editorial checks per segment and then all segments: provider text length within the saved account capability (shared X validation), at most three hashtags, at most three mentions, and no repeated normalized paragraphs. Only the duplicate comparison normalizes whitespace/case/NFKC; original text and spacing remain unchanged. Descriptive counters include weighted length, factual media presence/type/alt coverage, explicit protocol URL count, hashtags, mentions, lines, question marks and a small explicit CTA lexicon. That lexicon counts signs, not semantic CTA fit; expand it only when descriptive requirements need more languages. Media belongs to the saved thread, not an invented segment assignment.

`dispatch-score-v1` sums normalized hook .20, clarity .20, discussion .20, originality .15, natural CTA .05, structure .10 and history .10, then multiplies by 100. Floating point fractions are preserved; only a display may round. History is .5 with `assumed_cold_start_baseline`, not historical measurement. Every required semantic property must have the exact question type and valid value; choice and score confidence below .7 suppress the aggregate while preserving components. Missing and invalid values remain unknown, not measured zero. `jev-confidence-startup-v1` is an uncalibrated startup policy. No Audience Fit, embedding or platform ranking weights are derived from a declaration or public source snapshot.

A new `x-post-analysis-v1` profile candidate pairs the genuine question and normalization references. Creation is an explicit current Owner/Admin command; review and selection remain separate existing lifecycle/CAS/receipt operations. The old create API defaults to the immutable `x-public-context-v1` meaning. Old unavailable references are never reinterpreted, migrated or activated. Bounded payload union validators enforce valid old/new pairs. The public X snapshot remains information only (`scoringInfluence: none`); Dispatch owns its formula and thresholds.

The existing Node-only pinned TypeSafe SDK client owns exactly one request, funding and settlement. Default-off flags, six-link EU processing evidence, credential-bound immutable price policy, expiry, separate analyzer-purpose budgets, absolute deadlines, zero hidden retry, 64KB response bound, unresolved holds, circuit/probe and current source/profile/role checks remain in force. Requested/resolved model and usage remain on the one physical attempt receipt. Revocation can suppress result exposure without suppressing legitimate once-only settlement. No real provider processing, enablement, grants or production candidates were created to verify this feature.

`tests/evals/intelligence/post-technical-reference-v1.json` is a frozen AI-proposed technical fixture set, not a model inference run or human-reviewed calibration dataset. It covers the required content styles and edge cases with proposed expectation ranges. All rows and the dataset are `human_review_pending`. Whole AC3 remains unchecked until a human reviews the expected labels/ranges. Human acceptance of these fixtures and the complete EU/provider approval remain open; software checks do not certify either.
