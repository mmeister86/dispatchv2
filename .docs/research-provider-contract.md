# TASK21 — Native source search

This unit connects explicit human source queries to concrete X and Requesty transports. It does not run the Research Agent, verify claims, create evidence/clusters, or hand results to the Inbox. Historical TASK20 generation-prerequisite orders and prepared schedule callbacks remain inert. The new authenticated `research.native.start` is a separate explicit admission, with current membership, account identity, profile revision and immutable copied configuration. Subsequent profile edits do not change that snapshot; live pause/delete/stop and access withdrawal fence further work. Web permission does not depend on an X connection or publishing capability.

## Configuration and authority

There are three separately approved operations: public app-only X recent search, app-only X WOEID snapshot, and native Requesty ChatCompletions web search. There is no public policy/grant configuration writer or seeded approval. Each current tenant/account operation policy requires an actual Owner/Admin approver, finite expiry/generation, access, complete processing-chain, exact protocol/auth-mode, source rights, pricing, total-charge-bound and current lifecycle evidence. The existing `X_APP_BEARER_TOKEN` and `REQUESTY_API_KEY` server credentials are hashed and pinned in that proof; presence alone never grants access. The app bearer path is not an OAuth publishing/reconciliation credential bypass. User-context/private/protected/personalized X sources are unavailable in this unit.

Source approval pins the full current policy fingerprint and the three actual native-search grant IDs. Policy, credential, source proof, current grant purpose/version/currency/expiry, approver and live human/account/profile authority are checked before funding, again immediately before physical I/O, on cache hits and before source writes/projection. Public availability exposes only minimized operation/currency/guidance. Native profile cap configuration uses approved account-scoped native currencies without needing a generation policy; multiple currencies require explicit UI selection. No exchange-rate conversion occurs. Historical cap values retain their original currency through ordinary edits.

Production sources remain configuration-required until these actual proofs are configured. Evidence fields are operator configuration gates; synthetic strings, sample transport results or documentation are not verified live access, processing or pricing. Requesty's EU endpoint alone does not prove inference/search/gateway/logging/cache/retention/subprocessor residency.

## Financial ownership

Existing `aiBudgets` and `aiAttempts` remain the sole financial authority. Native-search is a separate grant purpose; generation run purposes are unchanged. The receipt schema is a backward-compatible union of legacy generation and concrete native search owners. Every generation receipt consumer (fund duplicate/unresolved checks, settlement, recent projection and personal-chat admission/authority/usage) uses the shared `generationAttempt` guard before terminal/idempotence/existence/projection shortcuts. It proves generation ownership, exact run/workspace refs, captured three grant IDs and their provider/workspace/account scope associations; chat callers also prove the run belongs to its operation/conversation/account. Valid late finance does not require renewed approval, grant expiry, policy, purpose or limits. Every native receipt consumer (settlement, result projection, cached fill ownership, historical unknown barrier and cumulative order cap) uses `nativeAttempt` to prove its actual filling order/cache/operation/captured policy/grant relationships before shortcuts. It validates exact three grant references plus tenant/account/currency scope independently of current source approval. A legitimate cache hit may refer to a prior filling order; it has no new financial attempt or current-call estimate. The shared `ai/accounting.changeLiability` owns transaction counter changes for the two actual caller families.

Native provider keys are `native:x` and `native:requesty`; workspace/account keys are `native:workspace:<id>` and `native:account:<id>`. X search/trends share the native X slice. Each source policy additionally requires current `allocationEvidence` and `allocatedProviderLimitMicros` exactly matching its native provider grant. The evidence must establish an allocated unreserved native slice excluding existing generation and reserved publishing capacity. These configured limits do not measure total external credit, and summing them with legacy generation limits would not prove global capacity. Combined external-credit and actual reserved-publishing measurements remain live acceptance gates. No grant is automatically created, no publishing financial state is changed, and no extra provider balance is claimed.

Before every physical request one transaction reserves a finite evidenced worst case in all three actual grants and counts every held/provisionally spent native attempt against the order's finite actual-currency cap. Immediately before I/O, the selected operation's own sent reservation must still match its actual order/cache/current generation and captured grant graph; each current grant's safe held-plus-spent total must remain within its limit. A late overage in another order can therefore fence this already-reserved request. This current physical-coverage check is separate from source rights, projections, authorized free cache hits and immutable late financial settlement: it neither erases delivered partial metadata nor forgives the old expense or new hold. X recent search reserves ten returned Post units; WOEID reserves one Request unit. Expansions and soft daily dedup discounts are unused. Requesty requires a genuine configured **total-request** bound including both inference and internal native-search fees; output-token limits, one HTTP request or Messages `max_uses` do not establish that bound. Missing total-bound/allocation proof blocks I/O.

Canonical version 2 logical intent includes workspace/account/operation and only the effective request inputs: X recent query, primary language and freshness clamped to seven days; Web query and full language; WOEID snapshot WOEID alone. It excludes profile/actor/version/order/cache/request wrappers, unused parameters and timestamps. Any sent/unknown receipt of that same intent prevents another paid attempt, including after time passes. A distinct source or genuinely different canonical query may continue if its own proof and remaining order/shared currency coverage permit it. Liability does not disappear on stop, revoked access, expired leases or new source IDs. Pre-v2 receipts retain their raw identity and all holds: an indexed exact workspace/account/operation/missing-version/state lookup conservatively blocks new paid work in that source family while any old sent/unknown receipt remains. Both legacy states are bounded to 100 results; overflow fails closed. Every inspected legacy receipt passes the immutable native ownership graph. One exact unchanged-snapshot cache probe preserves authorized completed/empty pre-v2 hits; there is no scan, guessed backfill or automatic paid retry. Up to 100 historical receipts per canonical intent and 30 attempts per order are inspected; exceeding either finite ceiling fails closed.

Native X known returned-unit counts create provisional estimates. Requesty reported floating cost remains unverified unless the captured `costCurrencyEvidence` explicitly proves the exact cost field's unit/currency; then it creates a provisional micro-unit estimate, not a billed invoice. Missing/corrupt/unfinished receipts retain the conservative hold and honest unknown usage. First observed unit/cost/invalid evidence survives unknown callbacks; invalid evidence remains sticky. Exact repeated known receipts settle once; conflicting receipts reject. Late known usage after stop/revocation can settle without restarting work. Overages remain booked and fence the order; caps do not waive expense. Billed amounts stay null. Cache hits create no new attempt and expose no current-call estimate or fabricated billed zero.

## Concrete transports and limits

All physical endpoints are fixed HTTPS, redirect refusal, bearer server-only, total request/read timeout at most 15 seconds and inside the order's 120-second deadline. No SDK, automatic retry, alternate provider/region or arbitrary source-URL fetch is used. Raw bodies/chunks/errors/tool intentions never enter ordinary logs or native Agent history.

X recent search uses `GET https://api.x.com/2/tweets/search/recent`, conservative query <=512 characters, explicit `post.fields=created_at,withheld,public_metrics`, no expansions and ten results on **one page**. A narrower last-seven-day window is recorded/displayed even if the profile requests 30–90 days. A next token marks truncation; this unit never claims full archive or full pagination. Numeric Post IDs, selected bounded text, actual publication time and canonical `https://x.com/i/web/status/<id>` are retained. Withheld/protected supplied records are excluded. Mixed valid data plus provider errors retains only individually validated public items as partial output, with unknown usage and the conservative hold retained; malformed items are never retained. Absent/rejected metric fields remain null, never zero. The chosen generated `post.fields`/`repost_count` protocol needs actual account compatibility proof because current guides differ. The WOEID path is fixed and separately approved, max ten trends, explicit `trend.fields=trend_name,tweet_count`; a region preference is not guessed into a WOEID. A snapshot count is not rising-trend evidence. X response bytes are bounded to 64 KiB. 429/failure is explicit, with no retry.

Requesty uses only `POST https://router.eu.requesty.ai/v1/chat/completions`, documented `tools:[{type:'web_search'}]`, stream=true, include_usage=true and max_tokens=256. The parser incrementally decodes fatal UTF-8, chunk-split CRLF and multiline SSE. It bounds aggregate input to 1 MiB, each event/line to 64 KiB, 512 data events, generated text to 16 KiB and 20 delivered sources. Only documented `choices[].delta.web_search.content[]` URL/title metadata is retained; model-invented URLs in text are discarded. HTTPS/no-credentials/standard-port metadata URLs are normalized without remote following. Completion requires valid finish, usage and `[DONE]`; error events, corrupt JSON/UTF-8, provider drops, EOF, conflicts and limits preserve partial supplied sources with an honest incomplete/unknown status. Generated prose is discarded. Delivered metadata cannot verify a factual claim, original event/publication time or trend growth.

## Cache, source lifecycle and actual copies

A cache key includes tenant/account/actor, profile version/copied configuration, query/language/window bucket, operation and full current source proof. TTL is at most five minutes; cache eligibility and source permission expiry are distinct. Completed/empty fills can be reused only with current authorization and valid source references. Partial/failed/unknown fills are not completed cache hits. Transactional fill ownership binds one actual paid receipt; lease expiry is never retry authorization.

Only `researchSources` holds selected source payload. Caches/order results retain source IDs rather than additional text/URL/title copies. Source rows retain exact provider identity, operation, current proof/generation, observed and publication times separately, retention/proof deadline and tombstone status. Owner/Admin invalidation against an actual same-workspace source clears URL/title/text/date/count and marks removed/blocked. A delayed fill cannot revive that tombstone. Scheduled native expiry clears retained payload under exact source generation/deadline CAS; current projection also hides withdrawn/expired source content. The real UI uses the existing proof clock to hide cached text and links at the earliest cache/rights/grant deadline while idle.

This unit implements actual stored-source invalidation, expiry, no-resurrection and projection barriers. It does **not** claim native batch-compliance entitlement, create a compliance job, upload/download supplied signed URLs, or measure provider deletion coverage. X retention/model-use requires actual current lifecycle evidence and finite proof deadline before admission; manual invalidation alone does not establish that coverage. No actual research evidence, embedding, proposal or Agent-context copies exist yet. TASK22/28/33/36 must extend this concrete inventory to their new copies and preserve tombstone/financial fences; no generic future-table engine is present. Human approved historical drafts and remote published posts are separate objects and are not automatically deleted here.
