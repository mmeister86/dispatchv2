# TASK33.1 — Unit 5 original bytes: smallest concrete implementation

Read-only preflight, 2026-10-09. Repository `/Volumes/Speicher/Projekte/dispatch_v2`. No source/Git/Backlog/deployment/test changes. Recommendation: one authenticated fixed-selector Node action returning bounded byte ranges, backed by one internal proof query and the existing S3 client. This delivers original files without a new R2 dependency, HTTP auth bridge, persisted export job, or a manifest falsely labelled as file export.

## Recommended action and proof signatures

New `convex/operations/exportMedia.ts` (Node) public `readOriginal` action:
```
{ workspaceId, expectedAuthId, expectedSessionId, requestKey,
  selection: {kind:"asset",assetId}
           | {kind:"draftVersion",versionId,mediaPosition,accountId},
  offset, expectedChecksum: string|null }
-> {authId,sessionId,requestKey,workspaceId,selection,role,
    assetId,name,mime,size,checksum,offset,nextOffset,done,
    observedAt,proofValidUntil,sourceUntil,bytes:ArrayBuffer}
```
Use `v.bytes()` explicitly, all fields allowlisted, fixed512KiB maximum chunk, offset safe nonnegative integer aligned to chunk size and <size (last chunk shorter). First offset0 expects checksum=null; continuation requires exact original first response checksum. Do not accept key,bucket,r2AccountId,URL,storageId,arbitrary byte end or component file ID. Domain selectors are mutually exclusive validator branches. Name is sanitized only for filename use; preserve original metadata name in manifest. A fixed asset branch is sufficient for library exports; the fixed draftVersion branch is necessary when claiming delivery of media belonging to an archived exact version. It must not fall back to library authority when that version's source expired. If Idea candidates are part of the intended original-media selector, add one fixed candidateVersion+mediaPosition branch using candidateProof/ideaProofUntil; do not fabricate a Draft link or omit a candidate's protected-source proof.

New internal `exportMediaSource.prove` query taking same correlation+selection+expectedChecksum (no offset needed except validity):
1. Use existing requireWorkspace→requireUser→requireIdentity: BetterAuth getAuthUser verifies session record exists/unexpired, requireIdentity verifies emailVerified. Enforce selected current user's activeWorkspaceId===workspaceId, expectedAuthId and identity.sessionId exact, bounded requestKey (reuse operations/export*.begin contract). Require shared Owner/Admin for full workspace media archive; if a separate ordinary own/private media path is intended, define its original domain ownership explicitly instead of widening a shared selector. There is no account ownership field on mediaAssets.
2. For asset selector derive asset directly by ID in selected workspace. For version selector first require exact Draft/version/workspace/account (account may be null if supporting ordinary accountless Draft), version not unavailable, mediaPosition valid, exact ref and snapshot assetId, snapshot checksum/key. Use `draftResearchProof(ctx,ver)` plus existing original version horizon; no requirement that it is latest or approved/scheduled. `immutableMedia` is supplementary to these checks. Reject foreign parents before any object or component read.
3. Require the original asset/upload-session flat invariant above, namespace against current configured binding, ready/mime/size/checksum and legal MIME cap. No query of arbitrary key; no temporary object reads. Missing legacy session/binding is explicit reconciliation error, not fallback to configured bucket. Original upload-session expiresAt is an expired WRITE grant after finalization, not a reason to deny valid retained originals.
4. Return an INTERNAL descriptor with key/bucket/r2AccountId+checksum/mime/size plus safe metadata and source horizon. Set proofValidUntil=min(observedAt+30s, current exact session expiry if explicitly projected, every original+current retained domain source horizon). Never renew a saved source horizon. Initial live session check alone does not expose exact expiry; small30s handoff window is not proof that the session cannot be revoked during it. Query the pinned session's expiresAt internally if a precise session-bound deadline is needed.

Action steps: prove→configuration+requireR2Binding→GetObjectCommand({Bucket:serverBucket,Key:serverKey,Range:`bytes=${offset}-${end}`}) with abort timeout min30s/proof remaining→consume bounded async stream→prove AGAIN with same original descriptor/checksum→return only safe envelope/bytes. Require ContentRange exactly requested start/end/total, ContentLength exactly expected chunk size, actual byte count exact; reject missing Body, ignored Range200/full body, oversized/truncated/changing range, invalid response and expired proof. Destroy/abort body on bound/failure. Require original descriptor invariants unchanged across proofs (including key/namespace/size/checksum/version/role/session/account) before returning. No retries beyond a small explicit policy; default1 is simplest and lets user retry after fresh proof. NoSuchKey/404 MUST return a named export missing-object error; never an empty successful file or manifest-only success.

An expectedChecksum is an integrity pin, not authorization. Each chunk independently authenticates and proves current ownership. An optional server-derived ETag/IfMatch can tighten multi-request consistency but would require preserving that server pin; it is not a substitute for the stored SHA256. Minimal path can omit ETag and require final complete file SHA256==the stored checksum before browser delivery. Do not confuse provider ETag with content SHA256. Range responses deliver bytes to the authenticated client; unsupported/corrupt transfer must not create the final downloaded artifact.

## Browser handoff and bounds

Use existing authenticated `useAction`/ConvexReactClient. No manual JWT extraction, token URL, cookie handoff, raw S3 URL or new CORS route. This is a server proxy action, not direct public bucket download. Reuse the data-archive/data-export current-scope requestKey cancellation pattern; keep at most one active file and one range request, suppress stale responses on auth/session/workspace/account/selector/role/unmount changes. Validate response correlation, exact fixed selection, offsets, finite numbers, byte ArrayBuffer/length, unchanged checksum/mime/size and unexpired min proof deadline before accepting every chunk. Missing or failed chunk cancels the artifact.

Accumulate only one supported file ≤32MiB, never500 files in memory. At most64 sequential512KiB calls per file; set an overall bounded transfer timeout and explicitly abort/discard on exceeded work, no partial-success download. After last chunk assemble bounded Blob, verify exact total size and SHA256 with crypto.subtle.digest, then perform a fresh proof/check action immediately before one Blob URL download. The final recheck can be a lightweight `verifyOriginal` query for exactly the same selector+checksum/session; it must not fetch/store bytes or grant a public URL. Recheck frontend current scope after that response too. CreateObjectURL only after success; revoke URL after click/cleanup. Filename derived safely from stored name, never headers or path traversal. Browser memory may briefly hold chunks+Blob+digest buffer (~2–3x32MiB); fixed ceiling and one file make that explicit. A future streaming-to-disk UI is optional, not needed for present32MiB maximum. Offer individual original-file downloads from complete paged media manifest; if batching, bound count/total bytes and report exact success/failure per file rather than asserting one full all-workspace ZIP.

Revocation caveat: server reproof before/after each chunk plus final browser handoff closes avoidable stale-scope windows; it cannot recall already delivered bytes or guarantee an instantaneous revoke after the final check. State that accurately. Do not claim120s signed URL can be instantly revoked. Keep operation deadlines server-bounded and minimum with source grants; never extend source retention from a user-supplied new timestamp.

## Agent original files: exact pinned behavior and honest exclusion

Installed Agent0.6.4 (`convex/ai/provider.ts`) has no application file upload tool or explicit storeFile calls; normal chat/generation paths use domain text. However **do not assert raw files are impossible**: provider.ts:254 maps result.content preserving non-tool parts, Agent client/messages.ts:143 calls `serializeMessage`, and pinned `node_modules/@convex-dev/agent/src/mapping.ts:454,475` automatically calls storeFile for inline image/file ArrayBuffers >64KiB. `client/files.ts::storeFile` stores app `_storage`, adds deduplicated component files metadata; component schema.files has storageId/hash/filename/mediaType/refcount but NO workspace/actor ownership. It is not legal to globally dump files based on component availability.

Unit3 intentionally exports plaintext only and discloses its file exclusion; that is not a newly established Unit3 bug. Task33's complete original-media scope requires a separate supported attachment branch plus explicit unsupported states. The following is implementable with the installed native APIs, not a global component dump.

Metadata bound before get; require Blob nonnull, blob.size==metadata.size and expected current descriptor hash/size. Return `await blob.slice(offset,endExclusive).arrayBuffer()` at512KiB max after complete domain/message/file/metadata reproof. No storage URL sent or accepted. For a URL part, resolve only against files already referenced by that same message, comparing to server-derived storage.getUrl for a bounded number of candidates; never parse caller URL into an arbitrary storage ID or fetch remote host. Reproof after byte retrieval must compare parent/source validity, message original role/thread/user, selected fileId or exact inline content, file.storageId/hash and storage metadata size/hash to the pre-read descriptor; receipt pin includes message._id/order/stepOrder but message edit cannot substitute a different attachment under same index. ExpectedChecksum on continuation catches such replacement but does not replace the proof. Missing original or mutation causes whole selected-file failure. Do not export raw provider/tool args or response headers while doing this.

Storage runtime limitation: official storage.get supports whole Blob retrieval, NOT a documented offset argument; current docs did not confirm storage HTTP Range support. Therefore do not claim the Agent branch performs ranged storage I/O. Above the chosen cap return EXPORT_ATTACHMENT_TOO_LARGE and report that original as blocked, never declare complete delivery. R232MiB originals use real GetObject Range and do not have this repeated-read cost. Parent should pick and disclose the native storage ceiling/work budget before completion claim, not leave an unlimited hidden path.
