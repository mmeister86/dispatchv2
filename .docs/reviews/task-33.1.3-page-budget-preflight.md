## Decision

Four raw candidates + one aggregate materialWalk(32) + 128 queries / 512 documents / 512 KiB reads / 64 KiB wire is not a liveness-safe release envelope for all individually valid source graphs accepted by the existing helpers. Shrinking the page to one is the smallest useful structural correction; it eliminates aggregate ancestry/wire amplification, but DOES NOT establish that 128 queries or 512 KiB is enough for a single retained source proof. A resource error must fail the page, so replaying the same unchanged cursor with the same insufficient budget deterministically fails again. Never turn that into a successful omission or silently advance past the row.

## Walk semantics and repeated sources

pipelineAccess.ts:11-47: one walk has a shared counted set, remaining budget, active-path set, proof memo and resolved material memo. enterMaterial counts distinct protected identities, not depth, visits, documents or DB calls. An active ID is a cycle; counted completed IDs can be reused. Memoization is native proof reuse, not an additional export cache.

contentProof.ts:43-119: draftIdeaVersion reads its direct Idea or legacy reverse relation BEFORE the Draft proof memo is consulted. A sourceUnavailable row fails immediately; a manual row without Idea/candidate/cleanup/proof marker returns null without consuming a unit. Each distinct derived Draft version consumes its own draft:<id> unit. Repeating the same Draft uses its memo only after the source lookup; different Draft versions sharing an Idea reuse the Idea proof but each still consumes a Draft unit. Therefore shared ancestry does not make multiple version roots free.

contentProof.ts:124-189: Idea proof memo includes account constraint; active identity does not. Completed independent roots do not create a false cycle in sequential processing. Different account constraints repeat work while counting the same identity once. Pure leaf notes consume zero units but still read their Idea root. Recursive Ideas (run/input/non-note source) consume one. sourceAccess.ts:152-274 similarly memoizes retained run proofs by account constraint, counts recursive runs, and clears active identities in finally. Do not parallelize independent root proofs using the same active-path set: overlapping in-flight roots can be mistaken for cycles. Native existing sequential use is the safe pattern.

A helper-valid Draft with 31 recursive note Ideas plus a leaf note consumes exactly 32 units: Draft +31 recursive Ideas. A second distinct Draft using the same source raises STYLE_ANCESTRY_LIMIT because its additional root needs unit33. Four disjoint Drafts with eight recursive Ideas each need36 units although each separately needs only9. This is aggregate rejection, not invalid ancestry. Existing performance/experiments.test.ts:522-568,570-583,646-649 exercises the equivalent 30-ancestor/two-Draft=32 versus31-ancestor/two-Draft=33 boundary. That fixture is injected and has12000-character notes, exceeding normal create/edit note4000; it proves test coverage intent, not actual producer reachability. No runtime execution here.

One shared walk is appropriate if an operation deliberately promises a32-distinct-identity total across its entire aggregate. It is inappropriate as an accidental restriction on independent paged versions otherwise individually supported. The smallest native export choice is one raw candidate and at most one admitted row per transaction using the unmodified default walk32. Larger pages could use separate unmodified walks per candidate, but that multiplies DB/read ceilings and would need release/controls; no new walker or cache is required or proposed.

## Native business wire limits and exact projection

lib/editorialFields.ts:23-30,104-117: schema validators are shapes (unbounded v.string/v.array at schema level), not length limits. editorial.ts:512-524 validates whole JSON content <=32768 UTF-8 bytes, title<=200, orderedtext1..100 with each<=25000 UTF-16 units, media<=20, pillar<=200, strategy<=100. Account capabilities impose further limits for non-null account (556-567). createDraft validates content (599); save validates content and reason<=500 (698-699). Native creation reason is fixed (643). Schema-only/direct inserts are not proof of validated producer bounds.

Smallest business row: explicit version ID, Draft ID only if correlation is explicitly released, number, creation/createdAt clocks only if released, title, text (ordered string array), accountId (including null), pillar, strategy, reason. No workspace/actor/source spreads, media, checksums, source refs, provenance, assets or rich projection DTO. Version/Draft IDs should be justified correlation fields, not omission skeletons. Validate exact finite numbers and wire bytes after constructing the explicit allowlist.

Validated content contributes <=32768 bytes even before removing media. JSON reason500 UTF-16 units can require up to3002 bytes including quotes because reason lacks control-character filtering. One row therefore needs approximately36KiB plus released IDs/numbers/clocks/envelope. Two near-max validated contents can exceed64KiB after reasons/metadata; four can plainly exceed it. A cap1 row is the smallest way to preserve supported maximum content under64KiB without truncation.64KiB still needs a check on the complete response including actual native cursor/auth/session/envelope; unbounded legacy/schema-only rows and unbounded envelope strings are not certified by producer content validation. Wire overflow is a whole-page error, never truncation/omission.

## Loss versus whole-page failure

May omit the entire payload only on positively established current unavailability: exact requested Draft root absent; non-null content account absent; explicit retained sourceUnavailable/cleanup loss; positively proved expired horizon; positively proved original actor/access withdrawal or source deletion under the intended shared-Draft policy. If source proof returns a non-null horizon at/before the export observation time, treat it as unavailable. Null is legitimate for manual/shared note sources, not failure. Do not export IDs/title/reason/removed counts for omitted rows.

Foreign/malformed version.workspaceId, root.workspaceId, version.draftId, account.workspaceId, or current-version→root bindings; corrupt ancestry owner/account/run/request/source links; active ancestry cycles; STYLE_ANCESTRY_LIMIT, RESEARCH_PROOF_ANCESTRY_LIMIT and other resource-limit codes; transaction/read/wire failures; unexpected/native DB exceptions MUST fail the whole page. Current authenticated verified selected Workspace Owner/Admin/session failure also fails the page, not individual rows. Current root's version binding must be checked even when exporting historical versions; do not require each historical version to equal currentVersionId.

Critical limitation: losses in lib/sourceProof.ts includes ancestry limits, owner-invalid errors, reference-access-denied and coarse IDEA_SOURCE_CHANGED / GITHUB_CONTEXT_CHANGED / RESEARCH_CONTENT_SOURCE_CHANGED. Many branches combine missing and foreign/corrupt bindings under the SAME code (contentProof.ts:90-92,134-136,175-178; sourceAccess.ts:219-225,230-235). Checking error.data against that whitelist CANNOT distinguish authorized omission from corrupt ancestry failure. rethrowUnexpectedSourceError preserves unknown exceptions but is not sufficient export classification. The smallest safe no-helper-change policy is narrowly omit explicitly established root/account/flag/expiry losses and dedicated unambiguous withdrawal errors whose exact call sites have been reviewed; propagate ambiguous helper errors as page failures. If broad omission of missing ancestors is required while foreign ancestors must fail, that is unresolved with the current coarse helper contract: it needs a separately released typed-loss seam in the existing native helpers, not a second copied ancestry walker or blind presentation whitelist.
