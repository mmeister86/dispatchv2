## Small endpoint shape and authorization

Add two fixed-family page endpoints, e.g. `exportIntelligence.page` and `exportRecords.page`, plus `exportIdentity.page` for component-backed own Auth data. Each has an explicit discriminated args/return union, NOT caller-selected table/index/fields. Reuse final shared download-envelope behavior after its writer completes. Arguments: common expectedAuthId/expectedSessionId/requestKey/workspaceId, family, typed accountId and/or native parentId, native cursor, selector upper bound. No caller actorId/component IDs. Start at one protected candidate per page; finite clock/UTF8 wire validation and min original/current source horizon, fail whole on unexpected/resource/ancestry/foreign-binding errors.

`exportIntelligence.page`: Owner/Admin business data, with own actor selector for private routing/request intent; `exportRecords.page`: shared Owner/Admin versus own-recipient/actor branches explicit in validator; `exportIdentity.page`: current authenticated user's own component records only. Same workspace role is never an override for another actor's conversation, targeted Research, approved GitHub excerpts or recipient notice. A single family may have parent-scoped child variants rather than one endpoint per table.

Original IDs, dates, generations, status, human input, retained result and lineage belong in authorized data. Current UI aggregates, current selection, redacted catalog and newest20/latest15 lists do not substitute for original history. Raw provider/auth/configuration secrets, scheduler/claim/retry handles, execution keys, arbitrary provider/error/step payloads and copied vectors do not belong in JSON. Original model/formula/question/public-code content hashes may be meaningful provenance; distinguish them from credential fingerprints or private material hashes rather than stripping every hash indiscriminately.
