## Cache answer and smallest binding

**Yes: use a fresh bounded random requestKey on each click.** Current official [React client docs](https://docs.convex.dev/client/react) describe `useConvex().query` for one-off callbacks; they do not promise a network-fresh query for identical args. Pinned Convex1.46.0 `node_modules/convex/src/react/client.ts:707–730` calls watchQuery then returns Promise.resolve(existingResult) whenever localQueryResult exists. `browser/sync/client.ts:742–748` indexes that result by serializePathAndArgs, whose implementation in `udf_path_utils.ts:37–43` is function+args. An explicit button alone therefore does not guarantee fresh source authorization evaluation.

Minimum query args: exact selected workspaceId, expectedAuthId from the actual authClient.useSession user, and fresh requestKey (e.g. UUID generated for this click, server string bound1..64). Bound expectedAuthId as an input string as well. Never prewarm, subscribe with useQuery, optimistically set, or reuse a prior export key. The key partitions client/server query cache and correlates this response; it is not permission, an idempotent effect key or an export job. No persistent registry is needed.

Reuse workspaceQuery for live verified Auth → own app user → current membership/active workspace. Compare expectedAuthId to derived ctx.user.authId; reject mismatch before reading profile. Require ctx.user.activeWorkspaceId equals selected workspace for this mounted consumer. Fetch only the indexed own preference row. Missing row is unavailable rather than synthesized defaults. No userId/recipient/table selector/session authority is accepted from the client.

A minimal wire-only result wrapper may contain `{requestKey, authId, sessionId, data}`: requestKey is the bounded original correlation echo; authId is derived from ctx.user; **sessionId must come from actual `ctx.auth.getUserIdentity().sessionId`, not a client echo**. Existing installed authComponent.getAuthUser already proves that actual identity's session exists and is unexpired, then resolves the actual identity subject user (`@convex-dev/better-auth/dist/client/create-client.js:34–76`). Compare the native wrapper session/auth/workspace plus current request ticket to the actual captured UI session/scope before creating the Blob. This catches same-user new-UI-session versus still-old transport token as well as cross-user transitions. No new session helper or Store field is needed. If the wrapper omits native session correlation, only UI observed-session cleanup is proven; do not claim native transport-session equality in that variant.

The downloaded `data` payload omits authId, native sessionId and requestKey entirely. Its declared finite families stay own app-user ID/creation context, selected workspace, own role and original named profile fields; no Auth/component records or credentials. Serialize only data, never the entire correlation wrapper. Keep the complete wire response bounded64KiB (including wrapper overhead); fail honestly on oversized legacy rows rather than truncate/mark complete.
