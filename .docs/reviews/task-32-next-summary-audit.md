This follows the bounded two-slot proposal already recorded in .docs/reviews/task-32-current-native-notifications-source-plan.md:45; the slots are not source today. Avoid another event table, generic job registry, event copies, mail ledger, delivery-history option or provider activation. At most 25 original eligible IDs per slot plus explicit bounded coverage; do not claim global totals. A consumed or terminally removed slot cannot resurrect under role/source restoration. Slot replacement must not overwrite a pending occurrence or extend its horizon.

For a minimal summary payload, use safe parent references/codes with an explicit observed interval and coverage; resolve display from current authorized parent proof rather than persist titles, bodies, prompts, diff, private topics or provider text. Optional in-app eligibility is `inAppSummaries && corresponding category`; `email` alone never enables this unit. Missing opt-in is OFF. Keep requested security email and mandatory draft/publishing notices immediate and outside quiet time.

Use native scheduler patterns already present: research/schedules.ts planSchedule stores nextAt + scheduledJobId and runAt's a generation/at callback; fire rechecks active generation/at/current authority and exact occurrence before admission, then schedules next. It has no generic registry and provides the right existing pattern. Preference-save transitions need generation fencing/cancellation for stale callbacks; the internal callback derives recipient/workspace from preference root, never client recipient arguments. This is a pattern to reuse, not permission to schedule research execution merely to obtain a summary.

Quiet admission uses notification timezone, never browser timezone or profile timezone. At each callback and presentation admission recheck current preference/category, revision/timezone, recipient membership, active workspace, account/current original actor/private parent proof and captured horizon. For a same-day range, start <= local time < end is quiet; overnight range wraps midnight. Preserve current start=end validation. Rechecking on list/open prevents a cached delivered summary remaining visible after consent/source loss; required read/dismiss commands retain owned observed IDs and auth/session/request fencing.
