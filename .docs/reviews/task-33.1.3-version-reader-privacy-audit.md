## Finding

Existing shared Draft projection deliberately admits retained derived shared text after source viability proof. It does **not** establish the requesting Owner/Admin's archive rights to each original private conversation or targeted Research source. This is a fact about current access seams, not a claim of an existing UI bug. Existing workspace presentation and a release demanding current-reader private ancestry rights are distinct policies. Do not silently infer the latter from successful `projectDraft` or from Owner/Admin membership.

`draftResearchProof`, `ideaProofUntil`, `currentIdeaSource`, `retainedRunProof`, `currentEvidence`, `currentMaterialProof`, and `currentContext` have no reader argument. Passing the ordinary authenticated `ctx` does not fix that: their actor-check branches explicitly use the *recorded original actor*. Existing optional parameters are account bindings, not reader identity. Never pass a reader ID in those parameters or substitute the reader for the source actor: original-source viability remains independently required.

The usable private-reader seam is `conversationAccess(ctx, workspaceId, accountId, conversationId)` with edit=false (`convex/ai/conversationAccess.ts:13–27`). It calls `requireWorkspace` without an actor override, proves workspace/account/conversation ownership, and requires `c.actorId === auth.user._id`. Thus another Owner/Admin fails. Pair it with `historyAuthority` (`29–52`) for active conversation/current source horizons; historyAuthority alone has no reader check. Reader identity and export's selected-session authority still require the existing export boundary separately.

## Smallest correct release policy

For the proposed actual business text export retain title, ordered text, owned accountId, pillar, strategy and reason only (plus explicitly released immutable business version identity/number/clocks if root wants correlation). Do not spread versionDoc, projectDraft, root, source, actor, media references or assets. No other-person identities, raw authors/private chat/Research/GitHub bodies, config, media bytes/checksums/object keys, provenance refs/component handles or per-omission metadata.

Always repeat live verified reader/session/selected workspace and Owner/Admin role, native root/version/account binding, and original-source proof on every page. Reuse draftResearchProof with one materialWalk(32) across the page for source viability. It cannot be reused by a current-reader parameter to provide the additional privacy gate without changing its contract/traversal. Do not make an export mode weaken the existing shared projection.

If Root releases the shared-content policy alone, current shared projection demonstrates derived Draft business text is visible after original minima, independently of original private archive access. That release must explicitly say it exports already-shared derived Draft text and does not claim current-reader private ancestry authorization. It cannot claim absence of protected derived text merely because raw ancestry fields were stripped.

If Root requires the stated current-reader rights for protected derived ancestry, additionally gate every concretely discovered private conversation via conversationAccess+historyAuthority and exact order/run links. When a known private ancestor belongs to another user, omit the **entire version payload**, including reason/title; stripping raw source fields is insufficient. When private provenance cannot be proved with available native bindings, do not export that protected derived text. The smallest conservative first release may omit the affected provenance branch instead of building a second all-family graph walker; admit plainly proven manual/shared rows and source branches whose full relevant lineage can be proven. Do not classify all non-note rows as private or all note rows as private-free: runId/inputVersionId/candidate/legacy reverse lineage can carry ancestors even when source.kind is note. No universal user-original privacy grant exists in these helpers; actual own-chat binding is reusable, arbitrary user originals without that binding are not.

Known unavailable/missing/withdrawn source/root/private-reader denials can be explicit omission cases; do not use presentation's whole loss whitelist blindly. `convex/lib/sourceProof.ts:3–71` includes STYLE_ANCESTRY_LIMIT and RESEARCH_PROOF_ANCESTRY_LIMIT. Export must make ancestry exhaustion/cycles, resource/wire overflow, corrupt bindings and unexpected native DB errors whole-page failures, not routine omissions. `rethrowUnexpectedSourceError` (`75–83`) is useful for preserving unexpected errors, but its presentation-loss classification is insufficient alone. A missing eligible Draft root is known non-exportable; foreign/corrupt version→workspace/account bindings must fail, not silently skip.

Proposed bounded four raw-candidate native workspaceId-index window is progress/selection traversal with a separate admitted-row cap, one shared materialWalk32, total nested read and full response wire budgets. Those are new release choices. Native creation-time upper bound controls later-created selection, not mutable root/payload cleanup or atomic cross-request snapshot. Omit known unavailable/private rows and advance the native cursor without skeletons, title/ID/reason/removed count/raw scanned count. Successful empty pages may continue. Raw sentinel does not establish moreEligibleRows. Cursor/empty-page progression can indirectly reveal row distribution: no strict hidden-row-count invariance or cryptographic cursor secrecy claim. Keep workspaceComplete=false; traversal completion is not authorized historical-content completeness. Before RootSourceRelease settle whether shared-derived policy or current-reader ancestry policy is intended; the existing helpers do not silently settle it.
