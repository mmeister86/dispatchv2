# Exact saved-version Jev assessments

TASK-28.3 stores `jevAssessments` against actual workspace/account/draft/draftVersion IDs. `intelligence/assessments:analyze` accepts only authenticated saved-version targets and an operation key; arbitrary actor IDs, text buffers, questions and results are not public inputs. The existing Node-only analyzer remains the sole SDK/funding/settlement boundary. Analysis does not modify approval, scheduling or publishing.

`dispatch-assessment-input-v1` hashes the exact ordered complete thread and factual media state, immutable algorithm/audience IDs and executable refs/questions, normalization/formula/threshold versions, requested model and immutable policy identity, account identity/capability and exact saved version within its tenant. Original spacing/newlines/segment boundaries are preserved. Actor, operation key, deadline, current selection revision and transient source horizon are excluded. Cache sharing is intentionally limited to the same saved version. Changed audience/objective/account capability/profile/model/policy/version cannot inherit another meaning's result.

`dispatch-audience-objective-v1` makes the saved `content.strategy` objective explicit in the SDK's existing audience string alongside the declared audience description. It changes actual model input, not only a cache hash. Account capability actually supplies deterministic structure's text limit; account identity remains server-side scope/provenance rather than an inferred measurement. No account identifier is sent to the model. Public ranking context has no score weight and Audience Fit remains unavailable.

Every new request, exact replay and cache hit calls the existing full `current` admission contract: current editable membership, existing active workspace/account/draft/version, exact currentVersionId, full bounded typed research/GitHub lineage, current selected creator/reviewer/selector authority, media pins, default-off controls, complete EU/credential/policy/grant configuration and current supported rubric. Reads distinguish retained normalized historical mathematics from currently applicable results; a disabled analyzer or changed profile makes the retained result inapplicable rather than silently enabling processing. Protected proof failure hides both current and history. Selection revision can fence a physical call without changing semantic meaning.

`jevAssessmentRequests` is an immutable request descriptor, with only the original Request/deadline, semantic digest, source horizon and creation time. The optional `drafts.assessmentRequestId` is the latest-request fence. Exact replay cannot extend the deadline or change intent, and a superseded key cannot reclaim the fence. A new operation key is an explicit new attempt; unresolved physical receipts still prevent a second model call. The transactional `finish` mutation rechecks current admission, current fence and the exact owned immutable attempt receipt before writing. It never recreates missing parents. Action responses contain status only; current/history projections decide result visibility. Rejection of an output does not cancel legitimate authoritative financial settlement.

Assessments persist normalized answers, deterministic counters without segment text, complete score components/weights/confidences/startup assumptions and question/normalization/formula/threshold refs. Exact immutable profile IDs, input digest/version and owned attempt ID plus policy/requested-resolved model/usage/timing/selection provenance are retained. Usage timestamps mean internal usage recording, not a provider invoice; actual billed money remains unknown on the financial ledger. No additional draft, alt text, raw prompt, response, private report or SDK history copy is persisted. Historical reproduction means recomputing retained mathematical components with the pinned formula; it does not promise identical stochastic model inference.

`get` bounds its recent same-version fallback and performs an indexed exact semantic lookup. `history` paginates at most 20 rows and proof-projects each row; it returns explicit pagination fields. The real Composer panel subscribes to the saved ID, blocks dirty/conflicting/saving buffers, awaits actions, uses new explicit retry keys after failure, isolates workspace/account/version/role epochs and hides protected outputs at current or historical source deadlines even without a database notification. Previous results are labeled inapplicable while pending/failed/dirty. Demo controls remain confined to demo mode. Actual recommendations/adoption belong to TASK-29.

Protected cleanup reuses shared `research/contentCleanup:scrubDraft` to schedule bounded version purging. A 15-minute proof sweep pages 25 protected assessments and removes invalid derived rows, covering independent GitHub/source authority withdrawal as well as deadline expiry. Request descriptors are proof-checked in bounded pages and removed after withdrawal/missing parents or after 30 days. This descriptor retention is an operational replay window; permanent `aiAttempts` remain authoritative for paid-operation deduplication and unresolved liabilities. Source-free manual drafts and all financial receipts are preserved. There is no cache-fill or second financial ledger.

Data inventory for future export/deletion/restore: `jevAssessments` (tenant/account/exact-version normalized derived data and provenance), `jevAssessmentRequests` (tenant/actor operation descriptors without source text), optional `drafts.assessmentRequestId` (current fence), and existing `aiAttempts` (`owner=jev-analyzer`, financial evidence retained independently). Missing-parent guards and proof cleanup do not certify that TASK-33 export/workspace deletion or TASK-36 restore workflows already exist. Protected source withdrawal intentionally removes reproducible derived history.
