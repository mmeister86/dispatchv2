## Concrete consent and source boundary

The existing Owner/Admin repository `configure` command has a separate optional `contextRead` purpose, default false for legacy/reselected sources. It requires current access, monitoring and content permission. The existing native purpose admission counter and source generation advance together. Every actual source closure/reselection resets context consent; existing security proof, source authorizer and purpose actor checks remain authoritative.

A current Owner/Admin/Editor may deliberately request one exact historical signed signal using its real ID, the current repository generation and one to three explicit changed text paths. The original signal's generation, delivery receipt/digest/GUID, native event admission, signed facts and any recovery origin remain unchanged. A new receipt binds only this chosen signal to the current repository/provider/installation/name/privacy and consenting actor. It grants no general retrospective derivation. The previous signed-signal idea guard remains unchanged; a new typed `context` idea source checks its concrete approved receipt through the shared source boundary.

Current actor membership, workspace lifecycle, repository purposes, current entitlement proof, security barriers, source generation and the exact captured connection/credential generations are checked before token mint, before the compare, after network completion, before saving, before approval and before model/tools/final content use. Missing or withdrawn proof cannot be renewed by replaying a historical receipt. A withdrawn model approval after submission cannot be reenabled on that same receipt. Safe late usage remains independently settleable through TASK17.

## Smallest actual read

Only a non-created, non-deleted, non-forced Push with nonzero exact 40-character before/after SHAs is eligible. Release tags are not signed immutable commit SHAs; these receipts remain `needs_context` without token mint or model I/O. No speculative tag, branch or historical tree resolver exists.

The existing native installation credential action gains only the concrete `context` use. It requires the actual pending receipt and requests `{metadata:read, contents:read}` with exactly one proven `repository_ids` entry. The returned token/repository/permission/expiry receipt is validated; tokens remain server-side. Existing metadata-only callers retain their least privilege. Global environment installation IDs do not grant tenant authority.

There is one fixed-origin GitHub JSON GET `/repos/{actualOwner}/{actualRepo}/compare/{signedBefore}...{signedAfter}`, API version `2026-03-10`, no pagination query, no redirect and no retry. Existing transport limits are 15 seconds and 1 MiB. The bounded comparison is transient: unselected patches and commit messages are discarded, never archived or passed to the model. No Contents/download URL, full file bytes, symlink target, submodule URL or arbitrary model URL is fetched.

Both actual `base_commit.sha` and `merge_base_commit.sha` must equal signed before; status must be ahead. The complete returned commit list must match `total_commits`, be at most 20 and end at exact signed after. There must be fewer than 300 changed files. Divergence, absent/mismatched basis/head, truncated coverage or provider limits yield `needs_context`. These ceilings are explicit `ponytail:` choices; no incomplete comparison is called the full Push diff.

Only three explicitly selected changed paths, at most 200 characters each, with a conservative text-extension/path allowlist are retained. Hidden paths, traversal, credential/secret paths, binary/key/lock files and sensitive old **and new** renamed paths are rejected. Each retained patch is at most 2500 UTF-8 bytes. Every hunk's old/new counts and aggregate additions/deletions must match the actual supplied file counts; absent/binary/truncated/unsupported patches are rejected. This is selected patch evidence, not proof of regular-file contents or whole repository coverage.

Common credentials, private-key markers and control bytes reject the selected material without saving it. Pattern filtering is a reduction measure, not universal DLP or proof that all private details are suitable for publication. The human must inspect every concrete retained excerpt and explicitly approve its exact SHA-256 (base64url) hash, current source generation and actor-bound receipt before any model transfer. Unsafe or unprovable selections stay blocked; no automatic redaction success is invented.

## Interpretation and immutable handoff

The typed result permits only maintenance/needs_context/relevant, bounded summary/rationale/novelty/uncertainty, exact selected path references, exact quotes from those approved patches, title/perspective and questions. Every referenced path must have an actual supplied quote. Fabricated quotes, unapproved paths, unknown fields or a publishing instruction fail. Quotes prove the excerpt was supplied, not that an interpretation or personal achievement is true. Novelty/confidence are explicitly uncalibrated model interpretation with incomplete context and no measured adoption/performance/reach probability.

Maintenance or insufficient context stores its reasoned decision with no idea or draft. Relevant output alone reuses `insertIdea` to create one actual immutable idea/version with the real context reference, original signed facts, approved-context provenance/hash, model rationale/questions and run ID. The exact result fingerprint prevents conflicting repeated commits. All current model/source/actor/account/stop/approval fences are checked before domain writes. Provider failure retains null result and the original signal; unknown transport/currency/usage liabilities remain held by the reviewed budget implementation.

Later explicit `ideas.generate` on this context-bound idea reuses the current approved excerpts, not a hash-only label, and keeps the same shared source/context guards before every funded step and output. Existing idea edit/history/CAS and explicit clarified human draft handoff remain authoritative. Draft creation returns existing real editorial IDs only after exact reviewed human text/intent/account/revision. No approval, schedule or publishing mutation is called by enrichment.
