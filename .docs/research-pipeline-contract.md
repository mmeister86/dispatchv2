# Research workflow v1 (TASK22.2)

`research.pipeline.start` is a new explicit admission. It snapshots the saved profile version and binds the selected native operations, language, original actor, account and generation. Existing TASK20 admissions and prepared schedule callbacks do not acquire spending authority. Recurrence requires a new Owner/Admin `activate-workflow` command; it reuses the existing IANA/DST occurrence engine. Ordinary profile edits affect future orders; pause/delete withdraw retained material authority. Stop prevents new effects and clears pending proposals while preserving previously committed evidence under its current source rights.

The official pinned Workflow component (0.4.8) journals bounded steps. It does not journal source bodies, profile bodies, editorial history, model output or result payloads. The journal stores IDs, selected operation names and null results. Actions have retries disabled. Runtime continuation reuses the journal; explicit resume checks its actual status, reports already running without recreating any order/run/receipt, and only uses official restart for an otherwise still authorized terminal workflow. Stopped, expired and terminal unknown-funded orders cannot restart.

## Actual steps and ceilings

1. Reserve each selected native operation through existing cache/accounting handlers before dispatch. There is one liability ledger (`aiAttempts`/`aiBudgets`), not a full-cap second reservation. Native reservation dispatch authority ends with the immutable order deadline; held liabilities do not expire into retry permission; first dispatch records a receipt and obtains a fresh maximum 20-second I/O lease bounded by that deadline. Sent/unknown receipts never authorize another paid dispatch.
2. Prepare one bounded saved-profile question (450 characters, up to five exclusion tokens), at most ten confirmed editorial post portions and ten cluster candidates. History comes from actual `xPostAttempts` plus matching `schedules.externalPosts` and captured draft versions; `confirmedAt` is distinct from the planned schedule time. First-write verification and unconfirmed thread portions are excluded. Bounded coverage never proves absence.
3. Execute selected X/Web operations separately through the existing adapters. Up to three selected native operations retain independent limits, cache outcomes and failures. There is no new search provider or automatic paid retry.
4. Select at most ten actually delivered source references using round-robin across selected native operations, recording each actual delivered/selected/omitted count (native fills are bounded to twenty references per operation), canonical origin/content-copy groups and immutable hashes. Publication and observation remain distinct; missing publication stays null. Copy groups merge connected URL, provider-identity and normalized delivered-text matches; they do not establish independent corroboration. Omitted delivery is carried into the model prompt, deterministic evidence gaps and per-operation Inbox coverage, and otherwise successful results are partial. Legacy orders lacking this recorded coverage expose unknown/incomplete coverage rather than assumed completeness.
5. Bind one semantic Agent run, native thread/prompt ID, source hashes and policy version before I/O. Prompt sources are bounded to 600 characters each and titles to 150. Existing cluster titles are governed prior model interpretations, not factual sources. Their original delivery-order source dependencies and evidence lineage are flattened into technical references, limited to ten total source dependencies and ten context evidence references. Context exceeding the ceiling is skipped with incomplete coverage. Their earliest source/evidence horizon bounds the new copy lifetime.
6. Classify semantic topics with the existing funded generation path, then assign/update account-scoped clusters using revision CAS. Classification is interpretation with model provenance, not an embedding similarity/probability claim. New `research-semantic-v2` prompts support an optional bounded opaque local `topicKey` (1–64 characters); it declares grouping within that output and grants no database authority. Existing cluster IDs/revisions must be supplied/current and cannot also carry a local new-topic key. For v1-compatible output without a key, only exactly identical declared titles share a new topic; different titles never merge by similarity. Stable order/topic/output operation keys prevent duplicate new clusters, independent primary evidence remains separate, and replay of a completed stage does not increment revisions again. The configured Themenanzahl caps distinct semantic groups (existing cluster ID, local key or exact declared title), not evidence rows; strict output remains at most twenty items and one per selected primary source (at most ten).
7. Assess current source support, publication age, relevance, novelty, copies, confirmed history and missing coverage. Without a delivered time series, stored dynamics is the controlled statement that the topic is currently discussed and no increase is proven; arbitrary model growth prose cannot enter this field.
8. Store attributed source claims separately from interpretation, gaps and account perspective in real `researchEvidence`. Output must use exactly supplied source IDs/hashes, supplied cluster revisions, confirmed history IDs and literal quotes from delivered text. Proposed event dates require literal quoted support and remain unverified. Metadata-only sources cannot become article/quote claims. Model-origin run/prompt/policy/output provenance is explicit; it never impersonates human attestation.
9. Expose the real bounded Research Inbox projection. Every new result is Review and has no automatic factual/validity grant. `autoHandoff:false` is persisted as disabled; no IDEA/draft bridge, publication, approval or generated-content scheduling is performed. TASK23 owns explicit editorial handoff.
10. Record actual terminal disposition, nullable aggregate usage and next occurrence from a currently explicitly activated workflow schedule. Manual runs without such a schedule have null next occurrence. Empty is distinct from technical failure, partial coverage, budget exhaustion, cancellation and configuration absence. Unknown usage/cost is null with pending liability, never a fabricated zero.

All new effects use the current tenant/account/original-actor graph, immutable order deadline/generation and current source policies/grants/processing rights. Generation additionally preserves the existing connected-account gate, current provider policy and all three funding scopes. Native and generation held/settled liability must fit the same order cap and currency. The generation attempt retains its existing generation owner; the research linkage is on its run/order, not a malformed native attempt. Stop/withdrawal blocks domain writes and new calls while legitimate immutable late usage can settle once.

## Source material, copies and deletion

`currentMaterialProof` is the single implementation behind the effect-compatible `currentMaterials` wrapper. It checks all selected and flattened secondary dependencies at read and before/after model I/O, including their original delivery graph, exact material hashes, expiry and governed evidence lineage. Current Inbox/manual model-origin evidence projections disappear immediately when any dependency is withdrawn. Their display proof horizon is the finite minimum of current primary and secondary native source/policy/lifecycle/grant horizons, current generation grant expiries, saved source pins and governed evidence/context lifetimes. The Inbox projection’s legacy `retentionUntil` field is that display cutoff, which the existing idle clock consumes; physical database retention is unchanged and distinct. Historical display is not artificially cut off by a finished order’s execution deadline. Policy generations are authority fences, not material versions. A valid cache hit can have an older fill order; delivered-source authority remains checked through the selected order's actual cache graph.

Copied content inventory:

- Existing native cache/source payloads: retained/invalidated/overwritten through TASK21 handlers.
- `researchOrders.pipeline.pending`: temporary proposed title, annotation, perspective and event quote; cleared on stop, completion, failure or purge.
- `researchEvidence.payload` and human-review assessment quote/reason copies: governed payload with explicit model origin; indexed bounded cleanup also follows manual review lineage.
- Native Agent thread messages (prompt and output): source-bound dependency inventory; physical cleanup uses `threads.deleteAllForThreadIdAsync(...).isDone`, after claimed execution has actually finished. A crash with no finished receipt stays pending.
- Workflow journal: bounded technical IDs/status only; official cleanup's successful result plus actual empty/isDone journal inventory is required (fewer than twenty entries, below the native 256-entry batch).
- Cluster/source-binding/context-pin stores: technical references only, no copied source/title/body text.

Source overwrite/invalidation/expiry invokes indexed dependency continuation, ten binding owners per batch; each owner scrubs at most twenty evidence copies per continuation. It does not run an unbounded orders×sources×evidence loop. Older-hash continuations cannot remove newer retained material. Cleanup is pending until no evidence copies remain and native Agent plus Workflow cleanup are actually complete. Enqueuing a callback or a void SDK wrapper is not completion. Workpool operational metadata/provider-side retention is not claimed to be erased. Source lifetime never grants model-proposed validity; existing manual Owner/Admin validity review and immutable lineage remain authoritative.

## Verification boundaries

Permanent synthetic tests register actual published Workflow and Agent components and invoke actual admission, reservation, native adapter, generation funding, output, evidence and cleanup handlers. Physical provider calls are intercepted; no paid search/AI/embedding, live publication or policy/grant activation is used. Coverage includes old inert callbacks, all-ten-step empty completion, stable first-send receipts, combined-cap rejection, real funded full workflow, wrong/current-withdrawn authority before and during I/O, late finance once, previously committed evidence surviving stop, secondary cluster-source withdrawal and native message deletion, X outage with usable Web output, duplicate cluster stage replay, exact IDs/quotes, canonical copy origins and actual confirmed history.

The initial missing-module RED was harness setup. Forty existing native failures then exposed a real exact-validator adapter defect (extra `operation` forwarded to `cache.commit`), and registered funded execution exposed a real JSON-property-order binding comparison defect; both were fixed in actual handlers. Browser verification uses a synthetic reactive backend against the actual Research page, preserves Real/Demo isolation, existing buffers/language/idle proof expiry and exact failed-intent retry. These tests establish behavior and lifecycle fences, not live provider output quality or semantic accuracy.
