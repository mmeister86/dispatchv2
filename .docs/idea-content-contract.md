# TASK18 — Ideas and concrete content proposals

TASK18 code scope: durable manual ideas, immutable revisions/feedback, current signed-signal handoff, explicitly confirmed editorial drafts and bounded generative perspective proposals. Manual notes work without a connected generation account, model policy or Jev. Jev remains disabled; this implementation does not activate provider processing/prices/budget grants or establish a live J03 acceptance.

## Authority and provenance

Authenticated workspace mutations derive the actual user and current Owner/Admin/Editor membership. Workspace lifecycle and all referenced accounts/ideas/versions/signals/repositories are checked. A client label, free-text source or copied URL does not authorize a repository or conversation. Notes are explicitly **unverified user claims**, not proved personal experience. Signal facts come from the existing signed TASK15 domain event, with exact signal ID, repository ID and generation. Current TASK14 content purpose, source identity/privacy, authorizing actors and 15-minute access proof are required before new derivation and draft handoff. Historical evidence remains readable to workspace members; it is not a renewed permission.

Only bounded push/ref/SHA/count or published-release/tag metadata is forwarded. No private files, commit messages, diffs, release bodies or new GitHub requests are read here. TASK16 owns explicit scoped enrichment consent and reads. TASK19 owns actual authorized conversation mapping/history; no fabricated chat source or parallel messages store was introduced. Pasted conversation summaries remain declared manual user claims until that real mapping exists.

The model may propose a title, perspective, rationale and one to five questions through a strict bounded JSON projection. These fields are visibly **model interpretation / clarification required**. They never add to the server-derived `originals` facts. Unsupported experience/project accomplishments cannot become verified evidence: the human must explicitly confirm clarification and submit the exact reviewed draft text before a generated idea can be handed off. A model statement of publishing/creation, foreign reference or unknown output field has no authority and fails the typed result boundary. The proposal itself creates no draft, approval, schedule or public post.

## Durable stores and concrete APIs

- `ideas`: workspace, actual actor, operation key/exact-input fingerprint, revision/current immutable version, new/accepted/archived status, update time and optional exact historical handoff. Indexed by workspace/update time and workspace/actor/operation key.
- `ideaVersions`: immutable numbered version, actual actor/time, title, perspective, note/user claims, priority, typed source, original facts, rationale/questions and optional actual run/input-version provenance. Indexed by idea/number.
- `ideaFeedback`: actual actor, referenced input version, edit/reject/restore, bounded explanation, time and optional resulting immutable version. Indexed by idea.
- `contentRequests`: actual actor/workspace/account, exact source idea/version/revision, intent, operation key, actual funded domain run, result idea ID or null, time. Indexed by run; workspace/actor/operation key; idea/creation time. This is a concrete content operation receipt, not another agent/history engine.

`api.content.ideas.create/edit/archive/handoff/generate` are the current actual human commands. `list/history/feedback/generationStatus` are bounded tenant queries. Every paginated read permits 1–50 rows; UI reads 25 current ideas or 10 immutable revisions/feedback, and follows real cursors. Per-idea generation receipts show at most the five most recent operations. No global provider/account budget rows leave these DTOs.

Manual create deduplicates exact workspace/actor/operation intent; a changed payload under the same operation key is rejected. Edits use expected-revision CAS, append a new immutable version and actor-bound feedback, and retain any historical draft handoff. Archive/restore persists feedback and CAS; archive blocks new generation/handoff. Deleting or hiding an idea is not a publishing cancellation or approval.

`handoff` atomically invokes the existing editorial creation transaction (narrowly extracted as `createDraftTransaction`, retaining existing validation/media snapshots/events), saves the actual returned draft/version IDs and exact idea version/revision, selected account, human intent, reviewed text, clarification confirmation, actor and time. Repeated identical confirmation returns those same persistent IDs. A different account, revision, intent or text cannot rebind or overwrite that draft. Later idea edits preserve the original immutable handoff. Account capability violations remain explicit errors and preserve the input buffer; a human may instead explicitly choose an accountless editable draft.

## Official Agent and funded generation

The existing TASK17 `createRun` transaction was extracted without changing its original internal API. `generate` derives its actual actor and source pins from the current idea; no client can select a component thread/user, model, endpoint, provider setting, tool or raw source generation. It creates one stable official Agent prompt/thread and content receipt atomically, then schedules the existing fixed-provider `internal.ai.provider.execute`. Exact repeated operation keys return the actual existing run; changed input is rejected. New operation intent requires a new key and actual budget coverage.

The existing official Agent0.6.4 / AI6.0.300 / openai-compatible2.0.81 path still owns retries=0, no fallback, no embeddings/cross-thread search, current grant approvers/policy fingerprint/account sequence, bounded SDK context/tools, pre-request funding, sanitized metadata/errors and immutable usage settlement. The shared active run check additionally validates a bound content request's actual workspace/actor/account and current source idea revision/version/status before tools, next physical calls and final output. A source/role/lifecycle/stop/version withdrawal permits safe usage receipt settlement but prevents a new idea.

The production provider passes validated generation text to `internal.content.ideas.commitProposal`, a concrete typed post-result domain operation. It rechecks active run ownership, exact input version/current revision and source permissions in the same transaction as the derived idea/result ID. Repeated identical output creates one actual idea; different output under the same run is rejected. Only this actual saved result ID justifies the UI statement that an idea was created. Provider/parse/authority errors preserve the original idea and null result receipt. Unknown transport/cost currencies/invalid usage/overage retain the reviewed TASK17 liabilities and do not gain any retry or cost reset through this content path. Official messages remain in the installed Agent component.

The existing Ideas page dispatches explicitly to demo or real mode. Real-mode manual/create/edit/archive/restore/handoff/generate await acknowledgment and prevent duplicate pending submission. Operation keys remain stable on retries. Pending form fields are disabled; rejected/CAS/configuration requests retain their title/note/perspective/intent/text. Actual GitHub Signals now accepts a deliberate perspective and hands off the actual selected signed signal ID only when the current matching content generation/rights/proof is eligible. Failures preserve the input. Its own pending/unmount/current-eligibility guards do not claim success after a rendered permission withdrawal.
