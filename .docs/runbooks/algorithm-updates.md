# Controlled algorithm-source maintenance — TASK-44

Operator procedure for the released source-only contract. TASK-44 software is independently reviewed at `7427f01` and native existing EU Dev is verified; see [final validation](../reviews/task-44-source-updates-validation.md). Manual/live acceptance remains open. It grants no processing/provider consent or production model permission.

1. In real Operations → Algorithmusprofile, select the actual X account and exact base profile. Owner/Admin authority is required. The base is an immutable source reference; an expired historical base may be fully re-observed without making that old profile usable again. No arbitrary repository/URL or GitHub App credential is accepted.
2. Choose a lightweight public HEAD check to detect a new SHA, or an explicit full source re-observation when a fresh snapshot is needed, including unchanged SHA after the old observation deadline. Await acknowledgment. Exact retry uses the original command; it does not rerun completed HTTP work or renew its observation date.
3. Read the factual outcome, original/new SHA and times, complete changed-path coverage, all13 immutable raw-file hashes/links, acknowledged request/byte counts and any missing/truncated evidence. Pending or inspected-unknown transport counts are not finally acknowledged; reserved zero values do not prove zero traffic. The original terminal receipt remains unchanged when a delayed action returns. `unchanged` is a source observation, not renewed review. Failed/rate-limited/unknown is not up-to-date. Respect displayed notBefore and the account cooldown; no background polling/retry is configured.
4. Structural gaps block a new candidate: missing evidence path, unproved ancestry, genuine next commit page/count mismatch, inconsistent SHA or a request/deadline/byte/path ceiling. A human checkbox cannot override them. A first-only Link header is not a next page. Stored patch excerpts are bounded; explicitly inspect the full immutable comparison and every evidence link rather than treating snippets as complete.
5. Record human interpretation, source-only Dispatch impact, full-source review and rationale separately from source facts. Select only informational public context or the existing unchanged post-analysis rubric. The server's small fixed reference regression checks compatibility; it does not certify empirical Jev quality, X production behavior or reach. No public X coefficient is imported into Dispatch weights.
6. Create a fresh immutable draft from the exact successful observation/evaluation. Its seven-day source-review interval begins at observation and is an operational assumption. Review that draft, then explicitly select it with the intended Audience pair and current revision. Source checks/evaluation alone change neither selected IDs nor revision; explicit create/review/select are normal profile commands with native receipts/revisions.
7. To discard an update draft, use its explicitly labelled retirement action with a decision reason. This is the existing profile command and its revision/receipt semantics, not a fictitious proposal-only disposition. To reverse a mistaken selection, choose the actual prior Algorithm/Audience pair in history and submit a new current rollback reason. Retired/expired/unauthorized targets cannot be resurrected; if no eligible pair remains, explicitly select null and retain unavailable analysis.

Current evaluator authority is checked at review, selection/rollback, profile availability and actual Jev use. An evaluator's later withdrawal can make a derived profile unavailable even when its creator/reviewer still has access. Exact retries never reapply selection or refresh clocks. Account/role changes fence late UI replies; dirty input is retained for an explicit next action.

Existing assessments, cache semantics, calibration candidates, static formula/threshold and historical publication pins are immutable. A newly selected actual Algorithm ID is a new semantic identity and cannot reuse old-account/old-profile cache or calibration authority. Saved history is not recomputed. Publishing and financial receipts remain governed by their existing native contracts.

Public transport is fixed to `xai-org/x-algorithm`, HTTPS API/raw hosts, redirects rejected: max20 requests,45 seconds total/15 seconds each,2MiB JSON/1MiB raw file/6MiB cumulative,300 changed paths and bounded excerpts. Public unauthenticated GitHub quota is shared by IP, so account cooldown cannot guarantee availability. No scheduler, model call, repository setting or paid finance row is added solely for this source check.

Restore/export/deletion must include source check/proposal/evaluation records, base/new profile links and all actor references while retained assessment/model/publication dependencies exist. Restored observations/evaluations do not renew human authority, source deadlines, processing grants or publishing approval. Full TASK-33/36 lifecycle acceptance remains separate.
