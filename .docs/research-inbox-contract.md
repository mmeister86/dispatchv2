# Research-Inbox: concrete command contract

The account Inbox pages the existing `researchEvidence` compound account index (maximum 20 rows per call). Source text is projected only by current evidence proof, with publication, attributed event and observation dates separate. Immutable human Review, workflow outcome, physical retention and mutable ignored/archived disposition remain separate. Disposition uses revision CAS and bounded actor/key receipts; a lost acknowledgement cannot repeat or overwrite a later action.

Manual content handoff uses existing `research/handoff.consume`: exact evidence IDs, explicit editorial intent, Idea/Draft target, maximum count 1–5 and stable command key. A selected proposal yields at most one result; no padding. Receipts carry actual Idea/IdeaVersion and optional Draft/DraftVersion IDs. Readable unverified Review is permitted for an explicit human proposal, without automatic eligibility, approval, schedule or publication.

Ask-Agent creates one actual own domain conversation through `conversations.create`, then `attachEvidence` saves a deterministic bounded Review summary through the registered native Agent. The separate create and attach keys survive failure; retries retain the actual conversation/message receipt. Attachment rechecks current source, owned active thread and whole history. New message appends wait for every native incarnation's execution completion. Route IDs and source text are never authority.

Re-research admits a new explicit one-off Workflow from current selected evidence and the saved profile. It pins the exact existing typed source and finite horizon, and supplies the immutable topic to native search and semantic evaluation. The new child counts toward the existing shared 32-order proof bound before additional paid I/O. Descendant evidence, content, history and cleanup retain the original parent lineage; secondary-source withdrawal fences the whole descendant immediately. Manual one-offs carry no automatic authority.

Automatic handoff requires a newly saved `bounded-editorial-v1` option with count 1–5, target and editorial intent, followed by a distinct `research-workflow-v2` activation. Only newly scheduled marked orders capture the actor, activation generation, profile version and exact option. False configs, v1 activations, prepared/source-only work and old or manual orders remain inert.

The consumer runs after actual workflow finalization and after explicit human evidence review. Newly generated Review waits for an actual finite human research-context support assessment. Current source/model/author/reviewer/account/funding rights and the captured Owner/Admin activation authority are rechecked before insertion. Save, pause, deactivate or authority withdrawal removes automatic permission without rewriting the original model task's immutable configuration. The first eligible bounded selection freezes actual result IDs once; later reviews cannot fill or duplicate it. Underfill is explicit. Unresolved usage or an exceeded order cap blocks insertion; technical late usage and unresolved holds remain intact. No command approves, schedules or publishes content.

Missing provider processing, source rights, price, budget or model configuration is shown as configuration guidance. A key or checkbox alone grants nothing. The real React Inbox uses mocked Convex transport only in browser fixtures; these checks are not authenticated/live or user manual acceptance. Registered domain tests intercept native/model HTTP and exercise real Workflow/Agent persistence without GitHub or live paid calls.
