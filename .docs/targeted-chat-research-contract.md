# TASK23.2 — targeted research in a personal Agent conversation

`ai.conversations.research` is an explicit scoped domain command. It requires the original actor, workspace/account, editable current membership, the current saved Research profile/revision, bounded topic, language, operations and stable key. It reuses actual pipeline admission, current budgets, the profile's active-order slot and registered Workflow. The optional immutable `researchOrders.targetedChat` binds the original conversation/topic and durable native result-message receipt. Saved recurring configuration is unchanged. Retrieval and semantic instructions/evidence perspective use the targeted topic. Raw component thread IDs and URL hints grant no authority. Exact replay returns the actual order; contradictory replay fails. Unknown native receipts remain barriers across rotated retry keys.

Workflow completion saves one actual native assistant message from current finalized evidence, without another chat model call. The message distinguishes unverified annotation/source assertions, literal quote, interpretation, gaps and publication/event/observation dates; metadata-only sources cannot support factual claims. Empty, partial, configuration, cancelled, withdrawn and context-limit outcomes stay explicit. It waits for all existing native chat incarnations before appending. A later explicit chat send uses separate current `chat` funding and account connection; native Web search may work while funded generation cannot. No autonomous research model tool, policy/grant activation, automatic idea/draft approval, scheduling or publishing is added.

Run/conversation sources accept the existing exact Research primitive plus backward-compatible GitHub pins. New GitHub captures retain a finite deadline and optional exact signal/idea-version identity. Research pins can retain an exact originating idea version. `context-set` idea sources flatten 1–10 deduplicated primitive refs; an inherited pin is preserved when another selected immutable version also needs a pin. Current source proof checks evidence/material/model/assessment/grants, GitHub context/signal identity, referenced immutable version and parent idea status, account and the earliest captured horizon. Repository refresh, edits and replay do not renew a captured deadline. All history, streams, follow-ups, idea tools, actual Ideas generation, linked reads and draft handoffs use those guards. Compound refs are checked sequentially with the same existing 32-order active/resolved material walk, including published draft history; a repeated valid ancestor is reused, while cycles and the shared ceiling fail closed. Research version ownership and archived parent status are checked before that material cache is reused. No research-to-Note fallback is possible.

`researchCopyBindings` is a bounded reverse provenance link from exact evidence to conversation, idea version or run (exactly one internal target). Evidence withdrawal immediately fences reads and schedules existing copy/native cleanup. Closed UI projections also request cleanup of their own unavailable history. Copied idea/draft/feedback/comment text is scrubbed through existing cleanup functions. Chat run cleanup delegates to whole-conversation cleanup: every claimed incarnation must have `executionFinishedAt`, and native `isDone` must confirm traversal before local deletion. Other source-bound generation threads use the same concrete native receipt. Unknown holds and once-settleable late usage remain intact. A source binding marked removed means cleanup has been queued; it does not attest native erasure.

The real Agent UI awaits acknowledgments, keeps captured profile revision/retry identity through a lost acknowledgment, suppresses stale workspace/account/role responses, displays actual order outcomes and separates research continuation from chat continuation. Its finite proof clock hides native messages and clears protected prompt/topic/title/idea buffers on expiry or revocation. Existing Ideas shows research/compound source labels. All new schema fields are optional for populated old rows; no historical order is promoted to a new paid workflow.
