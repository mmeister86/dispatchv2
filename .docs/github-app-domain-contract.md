# GitHub App source contract — TASK-14/P04.01

This implementation is separate from GitHub sign-in. Source OAuth uses GITHUB_APP_CLIENT_ID / GITHUB_APP_CLIENT_SECRET, not Better Auth GITHUB_CLIENT_ID / GITHUB_CLIENT_SECRET. Global GITHUB_APP_INSTALLATION_ID is never a tenant permission. This unit does not ingest GitHub events, read repository files/diffs, call a model, generate content or claim live acceptance.

## Human authorization and bounded discovery

Verified current Owner/Admin in the selected workspace starts a ten-minute one-use OAuth state with S256 PKCE. Its verifier and App-user credentials use the existing AES-GCM integration keyring with distinct workspace associations. The callback's installation_id is ignored; only a fixed registered SITE_URL /integrations/github/callback is used. Claimed states are never retried after an unknown code exchange. StrictMode uses the same promise and removes the callback query before completion.

A successful callback verifies GET /user and GET /user/installations with the actual App user token and configured App ID. Traditional scope must be empty: fine-grained App/user intersection is the authority. Candidate installations are an Owner/Admin settings projection only. Discovery rechecks /user identity and /user/installations, then /user/installations/{verified id}/repositories. Suspended, mismatched or inaccessible installations never authorize a source. No arbitrary provider URL is fetched. API requests reject redirects and use a15-second timeout,1MiB response ceiling and GitHub API version2026-03-10; no automatic retries.

The installation chooser shows at most100 user-accessible installations; it explicitly identifies a larger inventory. Repository discovery reads at most10 pages of100, has a120-second start-of-step deadline and reports truncation (an in-flight request has its15-second bound). UI reveals50 at a time. Only actually returned, user-accessible repositories can be explicitly selected; at most100 selections per workspace. Selected sources missing from bounded discovery are conservatively disabled even if the inventory is truncated. A missing row never constitutes proof of absence beyond this bounded selection. No broad App installation enumeration or file/diff retrieval occurs.

Selection starts with access=true, monitoring=false, content=false. Access, monitoring and content are separate explicit purposes; content requires current access and monitoring. The 4000-character context is explicitly communicable, not an imported private file or model purpose. Every purpose/context change, removal, privacy transition and disconnect changes source generation. Public-to-private or private-to-public transitions stop monitoring/content until a new explicit purpose. Ordinary workspace projections show only selected sources whose human proof remains valid; settings may retain previously selected, visibly disabled rows for removal/reselection. No candidate repositories or installation inventory are sent through the ordinary list.

## Freshness, refresh and effects

Human repository authorization snapshots expire after15minutes. Convex query caching does not advance time: both Settings and ordinary Signals additionally use the same concrete client proof-deadline hook. One native timeout targets the next actual proof expiry; visibility restoration rechecks wall-clock time, and cleanup removes the timeout/listener. Expired cached Settings rows show the stale/resync state with purpose controls and pending enabling saves disabled while keeping local context edits/removal available; ordinary Signals hides expired rows. A fresh query receipt can renew the deadline without dropping an unchanged source-generation edit buffer. This display guard does not replace the backend enqueue/commit authorization guard. Explicit Repository-Auswahl laden refreshes verified existing selections; Quelle freigeben can reselect a disabled source, with monitoring/content off. No background source job may treat configuration presence or an expired snapshot as authorization. Source actions recheck current role, selected workspace, lifecycle, connection/credential generations, discovery sequence and observed repository generations before persisting provider results. Each inventory operation snapshots only its installation sources plus an explicitly selected existing target; closing another revoked installation cannot make this operation reject its own change. Missing-installation/repository closure changes generation once when access/purposes/proof are actually closed, rather than bumping an unchanged disabled source on every resync. A removal or changed setting during network I/O cannot be undone by late discovery. A disconnect during callback I/O cannot restore credentials.

Expiring App-user access defaults to eight hours and refresh to six months, as returned by GitHub. Non-expiring token responses omit expiry/refresh fields; no expiry is invented. Refresh uses a durable60-second lease plus credential generation. GitHub consumes both old tokens on success; the confirmed response must contain a different access/refresh pair. Unknown refresh outcomes and expired leases erase credentials and require reauthorization, never blind replay.401/403 close source access even with non-JSON bodies. A native15-minute cleanup cron deletes50 expired OAuth states and closes50 expired refresh leases per run. Key rotation accepts the existing previous key and writes renewed credentials with the current key.

Background source authority is independent of the human's currently selected UI workspace. It requires an active actual workspace, current Owner/Admin memberships for the connection authorizer and purpose actor, exact repository generation, current selected/access/monitoring/content purpose, connection generation, accessible installation and unexpired proof. Recheck before enqueue and before committing derived effects. There are no content jobs in this unit; TASK-15 consumes these concrete gates for factual ingestion.

`repositories.checkSource(ctx, workspaceId, repositoryId, generation, purpose)` is the shared guard usable in Convex queries/mutations. `internal.integrations.github.repositories.source` returns only providerId, installationId, fullName, private, communicableContext, purposeAt and purposeVersion after that guard. The purpose is monitoring or content. This is not a model/file/diff authorization.

`internal.integrations.github.app.installationCredential` guards the exact source, signs native RS256 App JWT (iat now-60s, exp now+600s, issuer App client ID), requests only repository_ids=[verified source id] and metadata:read, validates the returned one-repository/one-permission receipt and expiry, then rechecks the source. It returns token/expiry internally only. No global installation token is cached or sent to UI. Expanding permissions for future ingestion needs the concrete operation's least privilege; this unit has no general repository token API.

Disconnect clears local credentials, invalidates pending callbacks, closes all selected source purposes/generations immediately and keeps historical source rows. Remote revocation/deinstallation is not attempted and UI says so. GitHub login remains usable. Verified installation/auth revocation webhooks and signed delivery ingestion belong TASK-15; no unsigned webhook route or speculative framework was added here.

## Persistence, inventory and future lifecycle

- githubConnections: workspaceId, authorizer actorId, connection generation, credentialGeneration, syncSequence, status, GitHub identity/login, bounded proven installation metadata, inventoryLimited, encrypted envelope, actual expiresAt/refreshExpiresAt, leaseUntil, updatedAt, stable errorCode. One row perworkspace; indexes by_workspaceId and by_leaseUntil.
- githubOAuthStates: workspaceId, userId, digest, connection generation, optional encrypted verifier, fixed redirectUri, expiresAt and pending/claimed/connected/denied/failed status. Indexes by_digest, by_workspaceId and by_expiresAt. At most one pending workspace attempt; a new explicit attempt invalidates previous attempts.
- githubRepositories: workspaceId, providerId, installationId, fullName, private, selected/access/monitoring/content, bounded communicableContext, purposeActorId/purposeAt/purposeVersion=1, connectionGeneration, source generation, verifiedAt/proofExpiresAt and updatedAt. Retained provenance/tombstones are not current entitlement. Indexes by_workspaceId_and_providerId and by_workspaceId_and_selected. Bounded in-memory installation filtering happens only over the100 selected sources, not a full table scan.

OAuth state/verifier and encrypted user credentials are non-exportable. Future TASK-33/36 export/delete/retention/restore must explicitly cover these three tables and expire grants/callbacks before restored data can authorize new source work. Restoring a source row must not reactivate old proof; connection/source generations and15-minute proof cannot be fabricated. Disconnect/remove do not claim deletion of existing derived drafts or remote installation deletion. Deletion lifecycle is already fail-closed in current guards.
