# Research evidence and human validity review — TASK-22.1

Native delivery remains the only source authority. `research/evidence:create` accepts an existing order, a delivered source ID, its expected material hash, a command key and bounded manual annotations. It never accepts authoritative source URLs, titles, dates, provider proofs or profile facts. A legitimate cache hit can refer to an earlier filling order; the selected order/cache/attempt/policy graph is checked. Current workspace/account/profile, original research actor, source policy, grants, identity and X connection sequence are required.

One immutable record stores the human source assertion, optional exact delivered quote, own interpretation, data gaps, explained account relevance, explained novelty, uncertainty, freshness class and validity reasoning separately. Account perspective is captured from the order's immutable profile snapshot. Source material remains in `researchSources`; the evidence record captures its material hash, generation and observation time. The hash includes the actual content, metadata and retention horizon, so a replacement at the same policy generation invalidates old notes and delayed commands. Exact quote matching establishes text provenance only. It does not establish truth, attribution or entailment. External-looking instructions are ordinary text, never tool or permission instructions.

`research/evidence:review` requires Owner/Admin and creates a new immutable lineage record, leaving the original annotation and any prior review unchanged. The reviewer explicitly attests substantive support and supplies a finite expiry, a reason and a maximum publication age. The only current purpose is `research-context`; the version is `human-publication-age-v1`. The effective expiry is the minimum of the requested expiry, publication-age limit, evidence retention limit and current source/cache/policy/lifecycle/grant horizon. This is a human assessment, not automatically established fact or publication approval. A current reviewer role and original annotator role are rechecked on reads.

Event-based claims require a separate human-attributed event date and an exact delivered event excerpt containing its ISO date. The event basis is normalized to UTC day start and the persisted basis is `earliest-publication-event`; eligibility uses the earlier publication/event date. Other date formats or absent event timing remain Review. Observing an article again never resets an event's age. Non-event claims persist `publication` as their basis. Missing text/publication date/quote, unknown freshness, absent support attestation and consequential or contested claims without independent corroboration remain Review. Independent corroboration ingestion and additional freshness rules are outside this unit.

`research/evidence:list` returns current proof and purpose-specific eligibility, rather than trusting a stored status flag. It hides all copied content when source material, permissions, identity, profile, original actor or annotation actor is no longer current. Expiry alone cannot revive a result; neither can an old command receipt. The UI schedules both source and validity deadlines while idle and freezes failed commands through the existing exact-retry controls. A source material change remounts its form, clearing old input buffers.

The only new table is `researchEvidence`, indexed by order/createdAt, order/actor/commandKey and source/state/materialHash. Each order is bounded to 100 immutable manual/review records. Exact repeated commands return historical IDs without rewriting, reauthorizing or recreating data; conflicting key reuse fails. Retention expiry clears annotation/perspective and copied assessment reason/event excerpt/event date. Source overwrite, invalidation and expiry synchronously clear up to 100 matching copies (10 per source in a 20-source fill), then schedule indexed continuation until none remain. Overwrite continuation targets the old material hash and preserves newly captured material. Scheduling is pending work, not a completed-erasure claim; completion is demonstrated by actual empty remaining-copy inventory. Hashes, IDs, rule/actor/time metadata remain receipts; this does not attest provider or component erasure.

No paid generation, article retrieval, provider activation, cluster workflow, Inbox handoff, idea/draft conversion, approval, scheduling or publishing is introduced. Existing financial holds and unresolved provider usage are preserved; a free manual annotation or human review does not authorize another paid call.
