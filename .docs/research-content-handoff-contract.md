# Research → content contract (TASK-23.1)

`research.handoff.consume` requires current editable membership, a destination account, explicit normalized human intent, an ordered unique selection and a requested maximum (default 1, maximum 5). It creates only the selected number of proposals: underfill is honest, with no padding, generation, automatic approval, scheduling or publishing. Each result names its actual immutable idea/version and optional draft/version IDs. An assessment is research-context support/freshness metadata; it does not attest semantic truth or authorize publishing.

The request hash binds account, target, normalized intent, requested maximum, ordered exact evidence IDs, evidence fingerprints, material hashes, model output and assessment pins. Concurrent equivalent requests return the same result IDs even with new retry keys; additional retry keys receive technical aliases and cannot later change intent. Different explicit intent/count/selection is a distinct human request. Original/reviewed siblings and identical concrete proposal families cannot pad one selection. Distinct meaningful manual annotations remain distinct proposals. Review creates a new immutable evidence record; callers select that returned ID. Review lineage admits at most 100 ancestors per selected evidence record. Inbox ignore/archive uses separate revision/actor/disposition fields, never research outcome or cleanup state.

`currentEvidence` rechecks delivery, account/order/profile pins, source hash/generation/expiry, native grants, annotation actor and reviewer (including expired/ineligible assessments), model prompt/policy/output and all retained pipeline source/history/context grants. The exact evidence reference plus technical source/model pins and an assessment hash survives into immutable idea sources; draft versions retain the exact idea version. Known older GitHub handoffs resolve through their existing exact reverse relation, never source text. Protected generation/chat sends remain configuration-blocked until TASK-23.2 supplies a real source-bound Agent transport.

Reads project protected idea/get/list/history/feedback, draft/get/list/history/comments and calendar snapshots without exposing withdrawn content. Shared guards precede edits, handoffs, approval/first-write, publishing content reads/preflight and source-sensitive reconciliation reads. Technical receipt inspection and late confirmed external facts remain possible without a new publishing approval. Recursive retained research proof walks cache resolved orders, reject cycles, and admit at most 32 distinct retained orders per proof; older context must be flattened before increasing that ceiling.

Research copies inherit a finite proof horizon; edits/replays never renew it. Exact confirmed publishing history contributes the earliest current and immutable source deadline (including GitHub provenance) to descendant source proofs, pipeline retention, model deadlines, evidence and copies. Cluster context also captures its full parent proof horizon. The existing pipeline purge then removes Agent prompts and Workflow journals at that inherited deadline. It cancels only a running native Workflow; completed/canceled journals still undergo actual bounded cleanup and empty-journal confirmation. Indexed, bounded scheduled cleanup follows source withdrawal, pipeline purge and retention expiry through evidence → idea versions → feedback/draft versions → comments. It removes actual copied text (including idea handoff intent/text and version media alt) while retaining technical IDs, hashes, media byte references, approval/history receipts and thread positions. No new approved placeholder or financial ledger is created. Source-free manual content remains unchanged.

The existing proof clock covers actual store-derived consumers, Ideas and independent Calendar queries/dialog snapshots. It advances across successive deadlines and clears protected editor/comment/first-write buffers; unrelated manual dirty buffers remain intact. Browser fixtures execute actual React store/pages with mocked Convex transport. Registered Convex tests separately exercise authorization, canonical replay, underfill, cleanup hooks, legacy provenance, recursive cycles, late receipts and active-profile immutable I/O. They do not substitute for user manual acceptance or enable provider credentials.
